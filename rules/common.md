# 通用规则

## 交流语言

- 全程用中文交流

## 代码修改要求（必须严格遵守，否则直接拒绝本次代码修改）

- 严格执行“零格式漂移”：除非当前功能修复或语法修正明确需要，否则禁止修改空格、换行、import 排列、行宽拆分、空行等纯格式内容
- 修改代码时禁止顺手处理 `lint`、`prettier`、排版整理等非功能性问题；如果这些问题与当前需求无关，则保持原样不动
- 禁止执行 `eslint` 脚本或 `prettier` 脚本来自动修复代码格式问题；如果需要修复这些问题，请单独提交一个 PR 来处理
- 修改文件时禁止修复eslint错误或prettier错误
- 修改文件时不要做无关的重构或优化；如果需要重构或优化，必须跟我确认后才能进行
- 修改文件时需要控制尽量小的修改范围，控制较小的影响范围
- 新增类型、枚举、常量、方法时，如果需要导出，请先确认是否真的需要被其他模块使用，避免过度暴露内部实现细节
- typescript类型名称必须统一以 `I` 开头
- 不要做不必要的export，除非确实需要被其他模块使用，否则保持类型、枚举、常量、方法等的私有性，避免过度暴露内部实现细节
- 类型定义、utils方法尽量下沉到需要使用的模块中，避免集中在一个公共文件中，减少模块间的耦合和依赖
- 通用的类型定义、utils尽量上提到公共模块中，避免在多个模块中重复定义，减少代码冗余和维护成本
- 属性访问、方法调用时，建议使用可选链操作符 `?.` 来避免潜在的空值错误，除非你确定该属性或方法一定存在
- 谨慎使用三目运算表达式，除非极简的表达式

## 日志规范

- 使用 `console.debug` 而非 `console.log`
- 日志需要加系统前缀、业务前缀，格式为 `[{系统前缀}] [{业务前缀}] 描述信息`

```typescript
console.debug('[{系统前缀}] 菜单加载完成', menuList);
```

## 国际化

i18n键命名: `[系统前缀]_[功能]_[组件]_[元素]`

```typescript
// ✅ 正确
formatMessage({id: 'dbi_menu_new_dashboard'});

// ❌ 错误
formatMessage({id: 'newDashboard'});
```
